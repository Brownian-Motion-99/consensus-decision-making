## 已完成

### 遊戲流程

- **房間**：任何人都能在首頁開新房間，取得 4 碼房號，開房的人就是主持人。其他人輸入房號，或開啟主持人複製的連結加入。一台 server 可以同時開多間房，上限 100 間。房間只能靠房號進入。最後一人離開 30 秒後才收掉（一個人重新整理也回得來）；連續 10 分鐘沒有玩家或列席人員（例如開了房卻沒人取暱稱）也會收掉，還連著的人回到首頁。
- **取暱稱**：開房或輸入房號之後才取暱稱。暱稱可以重複，因為玩家是用隨機 id 區分。暱稱一定要是字串，最多 100 個字（以 code point 計算，超過時由 server 回錯誤，輸入框本身不設上限，因為它把 emoji 算成 2 個字），畫面上太長的會截成「…」，滑鼠移上去可以看全名。只有看不見字元（零寬空格等）的暱稱，會自動換成「匿名水豚」「匿名石虎」這類名字。
- **大廳**：顯示房號、「複製房號」「複製連結」按鈕和玩家名單（2–8 人）。主持人設定「一致幾次才結束」（1–99，預設 3），再按「開始遊戲」。
- **作答**：在白板上手寫或畫畫，也可以打字，文字會即時畫到白板上。答案送出後不能修改。白板輸出成 JPEG：有反指紋保護的瀏覽器（Ardia、Brave、Safari 無痕）讀 canvas 時會加雜訊，PNG 壓不下來，只打幾個字就超過 200K 上限；JPEG 不受影響。server 仍接受 PNG。送出之後才看得到作答進度。
- **公開與判定**：全員送出後，主持人按「公開答案」，接著判定「一致」或「不一致」。畫面會即時統計一致幾題、不一致幾題。
- **結束條件**：一致次數達到目標才結束。題目會無限循環，題庫用完就重新洗牌。
- **結算**：只顯示總題數和一致次數，不顯示每題的回顧。
- **中途加入與列席**：任何時候都能加入。大廳、休會、結算時直接成為玩家；題目進行中加入的人成為「列席人員」，畫面只顯示「下個議案開始時即可進入會議」，收不到題目和答案，下一題開始時轉為玩家。玩家加列席最多 8 人。重新整理就是用這個方式回來，server 不認人。
- **還沒取暱稱的連線**：和列席人員一樣收不到題目和答案。每間房最多 5 條，第 6 條會被直接斷線，訊息只寫「目前無法進入，請稍後再試」。
- **斷線與休會**：主持人斷線時，從玩家中隨機挑一位當新主持人。遊戲中剩不到 2 人時進入「休會」：保留目標和已判定的結果，還沒判定的那一題作廢；人數湊齊後主持人按「繼續會議」，從下一題繼續（已達目標就進入結算）。

### 體驗細節

- 音效：判定一致、不一致，以及結算時播放。載入時會依照感知響度（EBU R128）把三個音效都調到 -14 LUFS，峰值上限是 -1 dBFS。單聲道檔案會照左右喇叭同時播出的情況計算。回到大廳時會中斷結算音效。
- 手機操作：
  - 寫白板時不會選取到文字，只有作答畫面禁止縮放。
  - 有安全區域和底部留白，避開 Safari 的浮動工具列。
- 連線中畫面：心跳放大動畫，文字佔畫面橫向中間的 1/3。
- 首頁：畫面中間 1/2 預留了 logo 區塊，目前用文字標題代替。名稱太長，標題固定拆成「本次會議／我們採取共識決」兩行。
- 空白的白板中央有半透明的鉛筆提示。
- 提示訊息浮在畫面上方，不會推動下面的內容。

### 外網連線

- `npm run tunnel` 會啟動兩個容器：遊戲 server，以及建立 Cloudflare quick tunnel 的 cloudflared。終端機會印出 `https://xxx.trycloudflare.com` 網址和 QR code，免帳號，不用設定 router。`npm run tunnel:down` 關閉。
- **Sandbox**：遊戲容器只接在 `internal` 網路，不能上網，本機也沒有開 port；不掛載本機資料夾、檔案系統唯讀、非 root、拿掉所有 Linux 特權，並限制記憶體、CPU 和 process 數量。已實際驗證過以上各項。
- **限流**（`src/limits.js`）：每個 IP 每分鐘最多開 5 間房、最多同時 20 條連線，全站最多 200 條；每條連線每秒最多 20 則訊息。容器模式的房間上限為 20 間。
- **網路慢的連線**：上一份快照還沒送完時不送新的，送完後只補送最新的一份，每條連線最多只有一份快照在排隊。實測一個不讀資料的 client 收 50 次廣播：沒有修正時在 server 排隊 28.7MB，修正後固定約 0.6MB（一份快照）。
- **心跳放寬**：連續 3 次沒回 pong（約 30 到 40 秒）才當成斷線，避免網路慢的玩家在公開答案、收大快照時被誤判。斷線畫面只寫「重新整理就能回到會議室」，重新整理後依當下的階段列席或直接成為玩家。
- **排隊太多就斷線**：除了正在送的那份快照，一條連線還沒送出去的訊息（錯誤、通知）超過 1MB 就斷線。審查時實測，不讀資料的連線送 7MB 的小訊息，會讓 server 長約 400MB（每則都換到一則錯誤回覆）；修正後這條連線會被斷掉。正在送的快照不算進去，否則網路慢的玩家在公開答案時就會被斷線。
- **邀請連結**：從外網或區網 IP 開啟時，用瀏覽器的網址產生連結；用 `localhost` 開啟時，才用 server 給的區網連結。

public/sounds.js     音效（Web Audio，自動解鎖、響度正規化）

狀態機：`lobby → answering → revealed → judged → (answering | finished)`，每一步都由主持人推進。

## 已知限制

- **重新加入是以新人身分**：重新整理後回到同一間房，但 server 不認人，題目進行中要先列席等下一題，已送出的答案也不會保留。沒有個人計分，所以刻意不做認人。
- **休會的實機體驗還沒測過**：規則有單元測試和 WebSocket 情境測試，但列席、休會兩個新畫面還沒在手機和預覽頁上看過（`/?preview=observing`、`/?preview=paused&as=host`、`/?preview=paused-alone`）。
- **macOS 的系統密碼自動填寫**：在 Mac 上，房號輸入框會跳出密碼自動填寫。這是 macOS Tahoe 的系統行為，網頁擋不掉，已試過各種 HTML 屬性。手機上的狀況還沒確認。
- **置中有些微偏移**：內容上下置中時，底部為 Safari 工具列保留的 96px 也算在內，所以內容會比正中央略高（約 48px）。
- **調整面板的部分字級只能打字修改**：首頁標題（`clamp()`）和「連線中…」（`calc()`）的值不是單純的 px／rem，面板會顯示成文字框，沒有滑桿。「連線中…」的波紋大小另外寫死成視窗寬度的 1/3，改字級時波紋不會跟著縮放。
- **分享預覽只有文字**：還沒有 `og:image`。用 `localhost` 或區網網址分享時，LINE 抓不到預覽，要用 tunnel 的公開網址才會顯示。
- **Windows 不能直接用 `npm run start:lan`**：script 寫成 `LAN=1 node server.js`，Windows 的 npm 用 cmd 執行，不認得這種寫法。README 先請 Windows 玩家在 PowerShell 打 `$env:LAN=1; npm start`（沒有在 Windows 上實測）。要根治可以改成跨平台寫法（例如在 server.js 讀命令列參數）。
- **架設門檻仍高**：玩家要自己裝 Node.js，外網模式還要裝 Docker Desktop、會用終端機。曾討論打包成雙擊啟動（Mac `.command`、Windows `.bat`，加上自動開啟的邀請頁和 GitHub Releases），因為測試量太大先暫停。
- **tunnel 網址每次都會變**：quick tunnel 每次啟動都換網址。想要固定網址，可以在 Cloudflare 綁自己的網域（named tunnel），或改用 Tailscale Funnel。
- **網路極慢的玩家仍可能被心跳斷線**：心跳已經放寬成連續 3 次沒回 pong（約 30 到 40 秒）才斷線。但下載速度每秒 100KB 以下的話，收一份 1.8MB 的快照就要 18 秒，排在前面的資料一多還是可能超過。之前審查實測每秒 100KB 在 35 秒後被斷線（當時只容忍 1 次）；放寬之後還沒重測，等多人實機測試時一起確認。
- **走 tunnel 時，server 看不到玩家的網速**（待確認）：server 連線的另一端是 cloudflared，它讀得很快，資料改堆在 cloudflared 裡。所以「只收最新快照」和「排隊超過 1MB 斷線」在 tunnel 模式下可能作用有限。依照威脅模型，這兩個保護主要是防搗亂，影響不大；但上面的心跳問題在 tunnel 模式下一樣會發生。
- **依照威脅模型刻意不處理的**（見 PLAN.md「威脅模型」，對手只有朋友）：
  - 1MB 算的是 payload byte 數，不是實際記憶體。小訊息每則都有固定的物件開銷，審查實測：同一個 IP 開 18 條不讀資料的連線，256MB 的容器衝到 245MB。（之前寫的「理論上約 450MB、要佔滿很多間房」估算錯誤。）
  - 房裡有人反覆列席、離開，產生的通知可以把網路慢的玩家推過 1MB 上限、踢出房間；每次進出也會讓每位玩家重收一份快照。
  - 暱稱的 Unicode 邊界情況：私人使用區字元、只有組合符號、單獨的 surrogate 不會被換成匿名動物；101 個零寬空格會回「最多 100 個字」。
  - 房間閒置被收掉、連線換到新房間時，舊房晚到的 callback 會刪掉新房的快照大小記錄，最多多算一份很小的快照。
- **新標題的版面還沒在實機上確認**：兩行標題的字級是 `clamp(1.75rem, 10vw, 4rem)`，照計算在手機上不會超出，但還沒用真的手機或預覽頁看過。
- **暱稱重複時難以分辨**：兩個「小明」在畫面上看起來一樣。
- **主持人無法中途結束遊戲**：只能等到達成目標。人數不足時會休會，不會自動結束，所以休會時大家想散會的話只能各自離開。

### 品牌與美術（下一階段的重點）

需要的識別元件（依照現有畫面）：

- **必要**：主 logo（手機用的兩行堆疊版、電腦用的橫式版，SVG）、圖形標誌（名稱太長，縮小後要靠圖形辨識）、favicon／apple-touch-icon／PWA manifest、分享預覽圖（`og:image` 1200×630，文字部分已完成）。

- **CI**：推到 GitHub 之後，每次 push 跑 `npm test`。目前還沒有 remote。
- **Mutation testing**：用 Stryker 定期檢查測試有沒有真的抓得到錯。這次是審查 agent 手動做的，找到了 5 個缺口。
- **o11y**：server 印結構化 log（開房、開局、結算、斷線、限流、錯誤），前端的錯誤透過 WebSocket 回報給 server。
- **分工原則**：已知的問題類型（讓 server 掛掉的輸入、資料外洩）寫成固定測試；審查 agent 負責找新的問題類型。
- **grill-spec 還沒實際用過**：等下一個比較大的新功能時第一次使用，再依照實際情況調整題數和題目順序。

### 上線前要處理

- 部署平台：建議 Render、Railway、Fly.io，或 Cloudflare Workers 搭配 Durable Objects。GitHub Actions 只能做 CI 和自動部署，不能當 server。
- 依實際流量調整房間上限和限流數字（基本版的限流已完成，見「外網連線」）。
