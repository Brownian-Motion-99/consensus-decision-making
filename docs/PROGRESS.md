## 已完成

### 遊戲流程

- **房間**：任何人都能在首頁開新房間，取得 4 碼房號，開房的人就是主持人。其他人輸入房號，或開啟主持人複製的連結加入。一台 server 可以同時開多間房，上限 100 間。房間只能靠房號進入。最後一人離開 30 秒後才收掉（一個人重新整理也回得來）；連續 10 分鐘沒有玩家或列席人員（例如開了房卻沒人取暱稱）也會收掉，還連著的人回到首頁。
- **取暱稱**：開房或輸入房號之後才取暱稱。暱稱可以重複，因為玩家是用隨機 id 區分。暱稱一定要是字串，最多 100 個字（以 code point 計算，超過時由 server 回錯誤，輸入框本身不設上限，因為它把 emoji 算成 2 個字），畫面上太長的會截成「…」，滑鼠移上去可以看全名。只有看不見字元（零寬空格等）的暱稱，會自動換成「匿名水豚」「匿名石虎」這類名字。
- **大廳**：顯示房號、「複製房號」「複製連結」按鈕和玩家名單（2–8 人）。主持人設定「一致幾次才結束」（1–99，預設 3），再按「開始遊戲」。
- **作答**：在白板上手寫或畫畫，也可以打字，文字會即時畫到白板上。答案送出後不能修改。白板輸出成 JPEG：有反指紋保護的瀏覽器（Ardia、Brave、Safari 無痕）讀 canvas 時會加雜訊，PNG 壓不下來，只打幾個字就超過 200K 上限；JPEG 不受影響。server 仍接受 PNG。送出之後才看得到作答進度。
- **公開與判定**：全員送出後，主持人按「公開答案」，接著判定「一致」或「不一致」。畫面會即時統計一致幾題、不一致幾題。
- **結束條件**：一致次數達到目標才結束。題目會無限循環，題庫用完就重新洗牌。
- **結算**：只顯示總題數和一致次數，不顯示每題的回顧。
- **中途加入與列席**：任何時候都能加入。大廳、休會、結算時直接成為玩家；題目進行中加入的人成為「列席人員」，畫面只顯示「下個議案開始時即可進入會議」，收不到題目和答案，下一題開始時轉為玩家。玩家加列席最多 8 人。重新整理就是用這個方式回來，server 不認人。
- **還沒取暱稱的連線**：和列席人員一樣收不到題目和答案。每間房最多 5 條，第 6 條會被直接斷線，訊息只寫「目前無法進入，請稍後再試」。
- **斷線與休會**：主持人斷線時，從玩家中隨機挑一位當新主持人。遊戲中剩不到 2 人時進入「休會」：保留目標和已判定的結果，還沒判定的那一題作廢；人數湊齊後主持人按「繼續會議」，從下一題繼續（已達目標就進入結算）。

### 體驗細節

- 音效：判定一致、不一致，以及結算時播放。載入時會依照感知響度（EBU R128）把三個音效都調到 -14 LUFS，峰值上限是 -1 dBFS。單聲道檔案會照左右喇叭同時播出的情況計算。回到大廳時會中斷結算音效。
- 手機操作：
  - 寫白板時不會選取到文字，只有作答畫面禁止縮放。
  - 有安全區域和底部留白，避開 Safari 的浮動工具列。
- 連線中畫面：多語「連線中」輪播（`public/greeting.js`，用 GSAP）。Connecting、連線中、接続中、Connexion、Conectando、연결 중、Connessione 每 1.6 秒換一個：舊詞往上模糊淡出，新詞從下方模糊淡入，包住文字的容器寬度用隱藏的量測元素量出新詞寬度，再 tween 過去（`power3.inOut`），後面的小圓點才會平滑移動。字用主色，圓點用白板外框色。離開連線中畫面就停下，再回來從 Connecting 重新開始；系統設定減少動態時只換字，不做淡入淡出和寬度動畫。螢幕閱讀器固定讀「連線中…」。
- 首頁：畫面中間 1/2 預留 logo 的位置（已拿掉原本的虛線方框），目前用文字標題代替，拆成三行「本次會議／我們採取／共識決」。標題用「逐行揭示」（`public/title-reveal.js`，用 GSAP）：每一行包一層遮罩，字從遮罩下方帶 6 度旋轉翻上來（0.9 秒、`power3.out`、間隔 0.14 秒），最後一行用主色，下方一條細線由左往右畫出，停留 1.6 秒後整段往上收走並淡出，再等 0.5 秒重來，只要畫面還在首頁就一直循環；離開首頁就停。從連線中進來時，等啟動轉場把首頁浮出來（0.8 秒）才開始第一輪。系統設定減少動態時直接顯示完整的標題，不動。
- 換頁簾幕（`public/curtain.js`，用 GSAP）：大廳 → 作答（開始遊戲）、判定完 → 下一題的作答，這兩個轉換會播。三片直條簾幕（Charcoal Blue，`--color-curtain`）從上方依序落下（間隔 0.08 秒、每片 0.45 秒、`power3.inOut`）蓋滿畫面，蓋滿時才換成新畫面，接著簾幕依序往下收走，新畫面的內容由上到下淡入上浮（沿用柔和上浮，稍快：0.5 秒、間隔 0.07 秒），整段約 1.4 秒。簾幕蓋住畫面時會擋住點擊；轉場途中又要換到別的畫面（例如休會）會直接取消簾幕並換過去；系統設定減少動態時直接換畫面。
- 送出答案的轉場（`public/submit-transition.js`，用 GSAP）：作答中 → 答案已送出（同一個畫面裡的內容切換）。兩邊都有的元件（進度、題目、畫布換成已送出的圖、主席的「公開答案」按鈕）用 FLIP 平移：先量舊位置，換完內容再量新位置，滑過去（0.7 秒、`power2.inOut`）；內容變多後整個版面會重新置中，所以題目和畫布通常是往上移。只有作答中才有的（打字框、清除／送出按鈕）留一份複製品在原地淡出（0.25 秒），複製品會帶著打字框裡輸入到一半的字；只有已送出才有的（「你的答案（已送出）」標籤、作答進度）用同樣的 0.7 秒和緩動從下方 24px 浮上來，晚 0.15 秒開始、間隔 0.1 秒。只在畫面上還是作答的樣子、收到「已送出」狀態的那一次播放；重新整理後回到已送出的畫面、其他玩家的作答進度更新都不播。送出時先在背景解碼答案圖，轉場開始時圖已經準備好。播到一半離開會還原；系統設定減少動態時不播。
- 公開答案的轉場（`public/iris.js`）：全員送出、主席長按公開後，一個白色圓從「公開答案」按鈕的中心展開（0.55 秒、`power2.inOut`），蓋滿畫面時在背後換成公開答案畫面，再從同一點展開一個透明的洞（0.65 秒，用 CSS `mask` 的徑向漸層做，邊緣有 40px 柔邊），把白色轉入公開答案。一般玩家沒有那顆按鈕，圓從畫面正中央展開。白色圓蓋住畫面時會擋住點擊。同一個轉場也用在公開答案 → 結算（主席按「看會議紀錄」，圓從那顆按鈕展開，結算的文字和彩紙等洞開到一半時才開始，所以不會被白色蓋住）。只在這兩個換頁播放；系統設定減少動態時直接換頁。結算音效（`congrats.mp3`）從公開答案過來時，等白色轉場結束（洞開完）才播；其他方式進入結算時照舊一收到狀態就播。
- 答案相片卡與照片堆展開（`public/photo-stack.js`）：公開答案的每個答案是一張帶白色寬邊框的相片卡（圖在上，暱稱在下）。進入公開答案後，所有卡先疊在中央、各自歪斜 3～14 度，洞展開完 0.3 秒後，一張接一張（間隔 0.04 秒）飛到網格位置並轉正（0.7 秒、`power2.inOut`）；點一下疊起來的卡可以立刻展開。不做收回。網格用 CSS grid，卡片的位置是用 transform 先搬到中央，展開就是把 transform 歸零（FLIP 的原理，沒有用 Flip 外掛）。欄數依人數：1 人 1 欄、2 人 2 欄、3 人 3 欄、4 人 2×2、5～6 人 3×2、7～8 人 4×2；每張卡至少留 100px，手機放不下就少一欄（8 人在手機上是 3 欄）。答案沒有變的狀態更新（例如判定）不會重畫，也不會重播展開。只有從作答畫面轉進來才會疊起來；其他情況直接顯示網格。
- 結算的彩紙爆發（`public/confetti.js`，用 GSAP 和 Physics2DPlugin）：進入結算畫面時只播一次（從公開答案過來時接在圓形轉場後面，其他情況進入時直接播）。結算的文字置中（和下面的按鈕對齊，換行時兩行長度接近），從 0.5 倍彈性放大（`elastic.out`，1.4 秒），同時從畫面下方中央噴出 90 片紙片（主色、白色、天藍、綠色，約 3 成是圓的），噴出角度在正上方 ±38 度，初速隨機，讓最快的紙片飛到約 85% 的畫面高度；紙片受重力（1100px/s²）拋物線落下、同時旋轉（含 3D 翻轉），從 55% 的時間起淡出，約 2.6 秒全部消失。紙片層蓋在畫面上但不擋點擊。播到一半離開結算會立刻清掉；系統設定減少動態時不播。Physics2DPlugin 和 GSAP 一樣由 server 從 `node_modules` 提供。
- 判定結果的排版：公開答案 → 判定沒有轉場，上方的答案圖和統計列在判定前後完全不動。原本的兩顆判定按鈕（達成共識／未達共識）在同一個位置換成結果文字（「達成共識！」綠字、「未達共識…」灰字，置中），主席的「下一題」（或「看會議紀錄」）放在文字正下方，寬度最多 14rem、置中，和文字隔 16px。一般玩家只有結果文字。主席看到的區塊事先留好「文字＋按鈕」的高度，所以整個畫面不會因為按鈕出現而重新置中、上下跳動（代價是判定前下方多了一塊空白）。窄螢幕上結果文字字級會縮到 9vw 以內。
- 長按確認（`public/hold-button.js`）：主席的「公開答案」按鈕要按住 1.2 秒才會送出（避免誤觸，大家還沒看完就公開）。平常是 Honey Bronze 底、白字（和原本的主色按鈕一樣）；按住時，白底、黃字的一層用 `clip-path` 從左往右等速蓋過去，按鈕縮小到 0.96 倍。蓋過去的那一層自己帶一份黃字（`data-label`），所以交界兩邊的字都看得清楚。中途放開、游標或手指移出按鈕、按鈕被停用，都會讓它 0.25 秒退回、不送出；按滿後按鈕彈一下（1.05 倍）、文字變「已公開 ✓」（維持白底黃字），之後畫面切到公開答案。2 秒內畫面沒換（例如 server 拒絕），按鈕會還原。滑鼠、觸控、鍵盤（按住空白鍵或 Enter）都可以；只按一下不會有反應。這顆按鈕不套一般按鈕的「按下去變暗」，否則白底會變灰。系統設定減少動態時蓋過去的那一層還在，但不縮小也不彈。其他按鈕維持一般點擊。
- 按鈕：按下去時明度微微降低（`.btn:active` 套 `brightness(0.9)`，0.1 秒過渡）；停用的按鈕不會變。曾試過「游標擴散填滿」的描邊膠囊按鈕，使用者覺得效果不好，已經還原。
- 啟動頁轉場（`public/splash.js`，用 GSAP）：連線完成、從連線中進入首頁時播放一次，約 1.5 秒。連線中的字（正在輪播的那個詞和圓點）停住、呼吸一次（1.06 倍），再從畫面中央加速放大到 14 倍（`power3.in`）並淡出，像穿過它進入 App；放大開始後 0.15 秒起，首頁的標題區塊、輸入框、按鈕列每隔 0.1 秒從下方 10px 淡入上浮。放大期間連線中畫面留在最上面，播完才隱藏（`showScreen('home', { splash: true })`）。只有真的連線完成那一次會播，從大廳等畫面回首頁、預覽頁的 `?preview=home` 都不播；`?preview=splash` 可以看轉場。播到一半離開會還原；系統設定減少動態時直接顯示首頁。
- 進入大廳的「柔和上浮」（`public/fade-up.js`，用 GSAP）：大廳裡看得到的區塊（會議編號和複製按鈕、玩家標題、玩家名單、主席的設定和按鈕或玩家的等待文字）依照由上到下的順序，每個從下方 18px、完全透明浮上並淡入，間隔 0.14 秒、每個 0.9 秒、`power2.out`，沒有彈跳和縮放。只在從別的畫面進入大廳時播一次，大廳裡收到新狀態不會重播；播到一半離開會還原；系統設定減少動態時不播。
- 空白的白板中央有半透明的鉛筆提示。
- 提示訊息浮在畫面上方，不會推動下面的內容。

### 開發工具

- **預覽總覽頁**：`/preview.html`（手機）、`/preview-desktop.html`（16:9）。所有畫面並排顯示，可以切換裝置、縮放和身分。
- **劇本模式**：`/?preview=flow`，依序播放狀態切換，可以檢查動畫和音效。
- **調整面板**：在總覽頁用滑桿和色票即時調整 CSS 變數，所有預覽同步更新，按「複製改動」就能拿到要寫回的 CSS。
- **啟動模式**：`npm start` 只接受本機連線，用來改畫面；`npm run start:lan` 開放給同一個 Wi-Fi 的手機；`npm run tunnel` 用 Docker 和 Cloudflare Tunnel 開放外網連線（見下方「外網連線」）。
- **測試**：`npm test`，共 81 個，涵蓋遊戲狀態機（含中途加入與休會）、多房間與房間回收、限流、響度計算，以及啟動真的 server 從外面打的測試（`test/server.test.js`：物件繼承的屬性名稱當 type、超過大小上限的訊息、不合法的 frame、格式錯誤的網址，都不能讓 server 掛掉；不讀資料又一直送小訊息的連線會被斷線）。
- **規格拷問 skill**：`/grill-spec`，放在全域的 `~/.claude/skills/grill-spec/`，所有專案都能用（不在這個 repo 裡）。做新功能之前，依照心智模型的六層一次問一題，使用者先回答，agent 才公開事先寫好的推薦，兩者不一樣的地方就拿來討論，最後把結論寫進規格。這個專案特有的設定（文件位置、身分和階段、拿來乘的數字、接縫）放在 `.claude/grill-spec.md`，skill 會先讀它。
- **審查 agent**：`.claude/agents/spec-reviewer.md`，對照 PLAN.md 審查指定的 commit 範圍，要求每個發現和「沒有問題」都附上證據。
- **文件分工**：`README.md` 寫給一般玩家（怎麼玩、架設步驟、區網與外網模式、常見問題），假設架設的人會用 git 和終端機；開發者用的啟動模式、環境變數、sandbox 細節、預覽頁、測試和檔案說明移到 `docs/DEVELOPMENT.md`。
- **授權**：自訂的個人使用條款（`LICENSE`，中英對照，以中文為準）：可以為個人、非商業目的使用、自架和自己修改；不能散布本軟體或修改版、不能商用。重點和第三方素材表放在 `docs/DEVELOPMENT.md` 的「授權」。
- **音效出處**：三個音效都是 Freesound 的 preview。`correct.mp3`（StavSounds #546084）、`wrong.mp3`（KevinVG207 #331912）是 CC0；`congrats.mp3`（InspectorJ #484267）是 CC BY 4.0，必須標示作者。標示寫在 `docs/DEVELOPMENT.md` 的「第三方素材」。
- **公開 repo**：https://github.com/Brownian-Motion-99/consensus-decision-making（public，預設分支 `master`）。

### 外網連線

- `npm run tunnel` 會啟動兩個容器：遊戲 server，以及建立 Cloudflare quick tunnel 的 cloudflared。終端機會印出 `https://xxx.trycloudflare.com` 網址和 QR code，免帳號，不用設定 router。`npm run tunnel:down` 關閉。
- **Sandbox**：遊戲容器只接在 `internal` 網路，不能上網，本機也沒有開 port；不掛載本機資料夾、檔案系統唯讀、非 root、拿掉所有 Linux 特權，並限制記憶體、CPU 和 process 數量。已實際驗證過以上各項。
- **限流**（`src/limits.js`）：每個 IP 每分鐘最多開 5 間房、最多同時 20 條連線，全站最多 200 條；每條連線每秒最多 20 則訊息。容器模式的房間上限為 20 間。
- **網路慢的連線**：上一份快照還沒送完時不送新的，送完後只補送最新的一份，每條連線最多只有一份快照在排隊。實測一個不讀資料的 client 收 50 次廣播：沒有修正時在 server 排隊 28.7MB，修正後固定約 0.6MB（一份快照）。
- **心跳放寬**：連續 3 次沒回 pong（約 30 到 40 秒）才當成斷線，避免網路慢的玩家在公開答案、收大快照時被誤判。斷線畫面只寫「重新整理就能回到會議室」，重新整理後依當下的階段列席或直接成為玩家。
- **排隊太多就斷線**：除了正在送的那份快照，一條連線還沒送出去的訊息（錯誤、通知）超過 1MB 就斷線。審查時實測，不讀資料的連線送 7MB 的小訊息，會讓 server 長約 400MB（每則都換到一則錯誤回覆）；修正後這條連線會被斷掉。正在送的快照不算進去，否則網路慢的玩家在公開答案時就會被斷線。
- **邀請連結**：從外網或區網 IP 開啟時，用瀏覽器的網址產生連結；用 `localhost` 開啟時，才用 server 給的區網連結。

## 已知限制

- **重新加入是以新人身分**：重新整理後回到同一間房，但 server 不認人，題目進行中要先列席等下一題，已送出的答案也不會保留。沒有個人計分，所以刻意不做認人。
- **休會的實機體驗還沒測過**：規則有單元測試和 WebSocket 情境測試，但列席、休會兩個新畫面還沒在手機和預覽頁上看過（`/?preview=observing`、`/?preview=paused&as=host`、`/?preview=paused-alone`）。
- **macOS 的系統密碼自動填寫**：在 Mac 上，房號輸入框會跳出密碼自動填寫。這是 macOS Tahoe 的系統行為，網頁擋不掉，已試過各種 HTML 屬性。手機上的狀況還沒確認。
- **置中有些微偏移**：內容上下置中時，底部為 Safari 工具列保留的 96px 也算在內，所以內容會比正中央略高（約 48px）。
- **調整面板的部分字級只能打字修改**：首頁標題（`clamp()`）和「連線中…」（`calc()`）的值不是單純的 px／rem，面板會顯示成文字框，沒有滑桿。
- **分享預覽只有文字**：還沒有 `og:image`。用 `localhost` 或區網網址分享時，LINE 抓不到預覽，要用 tunnel 的公開網址才會顯示。
- **Windows 不能直接用 `npm run start:lan`**：script 寫成 `LAN=1 node server.js`，Windows 的 npm 用 cmd 執行，不認得這種寫法。README 先請 Windows 玩家在 PowerShell 打 `$env:LAN=1; npm start`（沒有在 Windows 上實測）。要根治可以改成跨平台寫法（例如在 server.js 讀命令列參數）。
- **架設門檻仍高**：玩家要自己裝 Node.js，外網模式還要裝 Docker Desktop、會用終端機。曾討論打包成雙擊啟動（Mac `.command`、Windows `.bat`，加上自動開啟的邀請頁和 GitHub Releases），因為測試量太大先暫停。
- **tunnel 網址每次都會變**：quick tunnel 每次啟動都換網址。想要固定網址，可以在 Cloudflare 綁自己的網域（named tunnel），或改用 Tailscale Funnel。
- **網路極慢的玩家仍可能被心跳斷線**：心跳已經放寬成連續 3 次沒回 pong（約 30 到 40 秒）才斷線。但下載速度每秒 100KB 以下的話，收一份 1.8MB 的快照就要 18 秒，排在前面的資料一多還是可能超過。之前審查實測每秒 100KB 在 35 秒後被斷線（當時只容忍 1 次）；放寬之後還沒重測，等多人實機測試時一起確認。
- **走 tunnel 時，server 看不到玩家的網速**（待確認）：server 連線的另一端是 cloudflared，它讀得很快，資料改堆在 cloudflared 裡。所以「只收最新快照」和「排隊超過 1MB 斷線」在 tunnel 模式下可能作用有限。依照威脅模型，這兩個保護主要是防搗亂，影響不大；但上面的心跳問題在 tunnel 模式下一樣會發生。
- **依照威脅模型刻意不處理的**（見 PLAN.md「威脅模型」，對手只有朋友）：
  - 1MB 算的是 payload byte 數，不是實際記憶體。小訊息每則都有固定的物件開銷，審查實測：同一個 IP 開 18 條不讀資料的連線，256MB 的容器衝到 245MB。（之前寫的「理論上約 450MB、要佔滿很多間房」估算錯誤。）
  - 房裡有人反覆列席、離開，產生的通知可以把網路慢的玩家推過 1MB 上限、踢出房間；每次進出也會讓每位玩家重收一份快照。
  - 暱稱的 Unicode 邊界情況：私人使用區字元、只有組合符號、單獨的 surrogate 不會被換成匿名動物；101 個零寬空格會回「最多 100 個字」。
  - 房間閒置被收掉、連線換到新房間時，舊房晚到的 callback 會刪掉新房的快照大小記錄，最多多算一份很小的快照。
- **輪播動畫只在電腦的 Ardia（Chromium）看過**：還沒在手機 Safari 和預覽總覽頁看過，「減少動態」的路徑也只讀過程式碼。「Connessione」最長，手機上沒有實測會不會太寬。
- **新標題的版面還沒在實機上確認**：三行標題的字級是 `clamp(2.25rem, 14vw, 5rem)`（最長一行 4 個字），照計算在手機上不會超出，電腦寬度看過，但手機和預覽總覽頁還沒看過。
- **暱稱重複時難以分辨**：兩個「小明」在畫面上看起來一樣。
- **主持人無法中途結束遊戲**：只能等到達成目標。人數不足時會休會，不會自動結束，所以休會時大家想散會的話只能各自離開。

### 驗證流程

- **CI**：推到 GitHub 之後，每次 push 跑 `npm test`。目前還沒有 remote。
- **Mutation testing**：用 Stryker 定期檢查測試有沒有真的抓得到錯。這次是審查 agent 手動做的，找到了 5 個缺口。
- **o11y**：server 印結構化 log（開房、開局、結算、斷線、限流、錯誤），前端的錯誤透過 WebSocket 回報給 server。
- **分工原則**：已知的問題類型（讓 server 掛掉的輸入、資料外洩）寫成固定測試；審查 agent 負責找新的問題類型。
- **grill-spec 還沒實際用過**：等下一個比較大的新功能時第一次使用，再依照實際情況調整題數和題目順序。
